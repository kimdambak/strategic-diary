# strategic-diary
전략 일기장

> 열심히 사는 것이 목적이 아니다. **내가 원하는 상태로 나를 옮기는 것**이 목적이다.
> 이 일기장은 하루를 기록하는 곳이 아니라, 상태변화를 설계하고 실행하고 검증하는 곳이다.

## 핵심 원리

일반 일기는 "무슨 일이 있었나"를 적는다. 전략 일기는 아래 루프를 돌린다.

```
현재 상태(As-Is) → 목표 상태(To-Be) → 갭 → 레버(내가 움직일 수 있는 것)
      ↑                                              ↓
   상태 측정  ←  결과 검증  ←  실험(작은 행동)  ←  계획(if-then)
```

세 가지 질문이 모든 기록의 뼈대다.

1. 나는 지금 어떤 상태인가? (측정)
2. 어떤 상태로 가고 싶은가, 그 차이는 무엇인가? (방향)
3. 이번 주기에 내가 능동적으로 바꿀 한 가지는 무엇인가? (실행)

## 세 겹의 주기

| 주기 | 질문 | 시간 | 파일 |
|---|---|---|---|
| 분기 (90일) | 어떤 상태로 이동할 것인가 | 60분 | `quarters/` |
| 주간 | 이동하고 있는가, 무엇을 바꿀 것인가 | 30분 | `weeks/` |
| 일일 | 오늘의 의도와 실행은 무엇이었나 | 5~10분 | `days/` |

위에서 아래로 내려가며 정하고(분기 → 주 → 일), 아래에서 위로 올라오며 검증한다(일 → 주 → 분기).

## 폴더 구조

```
strategic-diary/
├── README.md
├── state-model.md          # 내 상태를 어떤 축으로 볼 것인가 (한 번 정의, 분기마다 조정)
├── templates/
│   ├── quarter.md
│   ├── week.md
│   ├── day.md
│   └── experiment.md
├── quarters/               # 예: 2026-Q4.md
├── weeks/                  # 예: 2026-W46.md
├── days/                   # 예: 2026-11-14.md
└── experiments/            # 예: 001-아침-30분-공부.md
```

## 시작 순서

1. `state-model.md`를 채운다. (내 상태의 축과 현재 점수)
2. `templates/quarter.md`를 복사해 `quarters/2026-Q4.md`를 만든다.
3. 첫 주간 계획을 `weeks/`에 만든다.
4. 매일 `templates/day.md`를 복사해 `days/`에 쓴다. 길게 쓰지 않는다.
5. 매주 말 주간 리뷰를 쓰고, 유지/중단/시작을 정한다.

## 운영 원칙

- 기록보다 **결정**이 먼저다. 쓰고 나서 달라지는 것이 없다면 쓸 필요가 없다.
- 한 주기에 바꾸는 상태 축은 **최대 1~2개**. 다 바꾸려 하면 아무것도 안 바뀐다.
- 계획은 "if-then" 형태로 쓴다. ("아침 7시에 앉으면 → 먼저 30분 공부한다")
- 못 지킨 날은 평가하지 않고 **원인**을 적는다. (의지 문제인가, 설계 문제인가)
- 지표는 적게, 숫자로. 느낌만 쓰면 변화를 검증할 수 없다.
